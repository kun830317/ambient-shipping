# 三柱論命 · 命格書(BaZi Three-Pillar Analysis)

把年月日三柱轉譯成「讓人起雞皮疙瘩」的心理側寫式長篇命理報告。與四柱版 v6 共用同一條翻譯流水線:**命盤依據 → 心理翻譯 → 生活場景還原 → 行動處方**。

**定位:三柱論命是傳統命理處理「時辰不詳」的正規做法,不是殘缺版。**日主、月令、配偶宮(日支)、三柱關係軸、旬空、大運排列、流年干支全部不受缺時柱影響——八章骨架完整保留,只是部分判定要換一套「承認不確定性」的引擎。

## 與 v6 的一致性契約

三柱版是 v6 的**同級姊妹版**,不是簡化版。四個維度必須一致:

| 維度 | 一致性要求 |
|---|---|
| **章節結構** | 八章 29 節 + 附錄 + 一封信,與 v6 同構。唯一差異:v6 的 6-3「你的下一代」(純子女宮)改為 6-3「手足、同輩」(比劫宮位,不需時柱),節數不變 |
| **論點密度** | 缺時柱拿掉的論點,由三組三柱專屬論點補回(關係軸、旬空、宮位遞進軸);1-1 第二幕的機制條目由 v6 的 5 條增為 6~7 條 |
| **版面** | 共用 `references/report-layout.md` 與 `scripts/build_mingge_book.py`,同一組色票與版式;差異僅限命柱卡三張、命盤頁三欄不列真太陽時校正、多一頁附錄 |
| **風格** | 共用同一套寫作鐵律;三柱版僅多第 12 條(不確定性的寫法),不改動前 11 條 |

## 時柱缺位的三類影響(全書設計基準)

| 類別 | 內容 | 處理方式 |
|---|---|---|
| 直接消失 | 時柱十神、時支藏干、時柱神煞、子女宮、晚年宮、私領域深層宮、真太陽時校正 | 相關主題整篇不寫,**嚴禁虛構或硬掰**;子女與晚年只在附錄解鎖清單出現一次 |
| 精度下降 | 身強弱、五股力量值、五行分布、用忌神 | Stage 1 跑數值化「翻盤測試」定 confidence,必要時保守判定 |
| 完全不影響 | 日主定性、月令、配偶宮(日支)、三柱關係軸、旬空、格局、大運排列、流年干支 | 照 v6 原樣處理,力度不打折 |

## 執行流程總覽

```
[收集輸入] → [Stage 1:十六步推導鏈 → 命盤技術檔案 JSON(含力量值與 confidence)]
           → [Stage 2:依 JSON 逐章寫作(八章 29 節 + 附錄 + 一封信)]
           → [自檢清單] → [輸出 .md + 依版面規範渲染 PDF]
```

**鐵則:Stage 1 的 JSON 是唯一事實來源。八章所有論述必須可回溯到 JSON 的具體欄位,絕不在寫作中途改變身強弱判定、力量值、用忌神、流年機制。JSON 裡沒有的時柱資訊,文章裡一個字都不能出現。**

## Step 0:收集輸入

必要:三柱(年柱/月柱/日柱干支),或出生年月日(國曆/農曆擇一,標明清楚)。

**兩個必問(三柱版專屬):**
1. 「出生時間真的查不到嗎?」——提示可查出生證明、戶政資料、醫院記錄、問長輩。查得到就改用 bazi-deep-analysis 跑完整四柱,品質更高。查不到再繼續。
2. 「家人有沒有印象是白天還是深夜出生?」——若可能在 23:00 之後出生,日柱有換日爭議,**日柱本身存疑**。此時在命盤頁標註「若確認為深夜出生,建議以隔日日柱重排核對」,不可裝作沒這回事。

建議追問(缺了也能跑,但品質下降):
- 稱呼、性別、婚姻狀態(影響感情篇整章的寫法:已成家者改談伴侶輪廓與相處機制)
- 出生年份、出生地(用於流年歲數;出生地不影響三柱,但命盤頁會列)
- **大運排列與起運歲數**(若未提供,依月柱+年干陰陽+性別推排並標為推算值;無時辰時起運必然是推算值,一律 ±1 歲彈性,建議用排盤軟體核對)
- **user_context**(職業、興趣、現況、家庭處境)——這是個人化注入的殺手級素材,決定報告是「準」還是「你是不是在我家裝監視器」。事業篇與貴人篇特別吃這個

若使用者給出生年月日而非干支:年月日三柱換算不涉及時辰與真太陽時,風險比四柱低,但月柱仍有節氣交界日問題——生日落在節氣交替前後兩天內時,先驗算節氣再定月柱。**干支、旬空、流年、六十甲子序位一律程式驗算,不心算。**

## Step 1:三柱排盤引擎(Stage 1)

讀取 `references/stage1-engine.md`,依其十六步推導鏈產出命盤技術檔案 JSON。

要點:
- 推導依序執行不可跳步(基礎驗算→**力量值量化**→通根→身強弱+翻盤測試→**三柱關係軸**→格局命名→**三塊地形圖**→十神→**旬空**→神煞→**宮位遞進軸**→用忌神→大運+走勢評分→關鍵流年+窗口→六親人際→時辰解鎖)
- **力量值量化是 v6 的信任裝置**,務必產出五股數值。三柱版標 `base: six_char`,只在盤內比比例,**嚴禁與四柱盤比大小**
- **翻盤測試要數值化**:兩個極端下五股各自最多變動多少、判定會不會翻,據此定 confidence 與 prescription_mode
- **三組補償論點務必跑滿**(關係軸、旬空、宮位遞進軸)——少跑一組,報告就會比 v6 薄
- 地形圖**恰好三塊**(本位/近景/遠景),不畫第四塊、不提時柱、不解釋為什麼三塊
- 關鍵流年只認年支/月支/日支與天干的互動;連續成局併入 key_windows

先把完整 JSON 呈現給使用者(或寫入工作檔),確認無誤再進 Stage 2。若使用者對判定有異議(如身強弱),在 Stage 1 修正後才續寫,不可在章節裡「將錯就錯」。

## Step 2:章節文案引擎(Stage 2)

1. 先讀 `references/writing-rules.md`——十二條寫作鐵律 + 風格範例。**第 2 條「三層寫法」與第 3 條「數字要出場」是 v6 的招牌節奏,最容易漏**
2. 再讀 `references/chapter-templates.md`——八章 29 節的節次任務、新素材配置表、附錄與一封信
3. 依序寫八章,不可亂排:性格 → 財運 → 事業 → 感情 → 健康 → 家庭六親 → 大運 → 貴人 → 附錄 → 一封信
4. 邊寫邊用 `references/report-layout.md` 的標記語法(`@terrain`/`@os`/`@callout`/`@bars`/`@dayun` 等)

每節寫完立即對照模板的節次要求檢查,缺項即補。**跨章互指全書至少 5 處**(「第八章那條路」「第五章給對策」),那是 v6 的黏著劑。

## Step 3:自檢清單(交付前必跑)

與 v6 共通:
- [ ] 每個論點是否走完四步公式(依據→翻譯→場景→處方)?
- [ ] 1-1 第二幕與各章機制段是否都有三層(意象/命理含數字/日常)?
- [ ] 力量值數字是否確實出場(講壓力給官殺值、講救命的給印值、講落差做相加對比)?
- [ ] 性格描述是否用矛盾結構而非形容詞堆砌?
- [ ] 全書內心 OS 直寫是否 4~6 處?
- [ ] 所有年份預測是否附命理機制?所有負面判斷是否附條件式出口?
- [ ] 建議是否具體到「明天就能做」(顏色到色系、年份到干支、期限到年月、話術給實際句子)?
- [ ] 八章的身強弱、力量值、用忌神、格局定調是否與 Stage 1 JSON 完全一致?
- [ ] 有 user_context 時,財運/事業/感情/貴人四篇是否各錨定一次?
- [ ] 感情篇 4-3 是否維持「氛圍與情緒共鳴」層次、點到為止?
- [ ] 每章末是否都有 callout(身份重塑句)?跨章互指是否 ≥5 處?
- [ ] 一封信是否零術語(不出現十神名、干支、力量值)?

三柱版專屬:
- [ ] 全書是否零時柱內容?(未出現任何時柱干支、未寫子女宮/晚年宮/私領域深層宮論斷)
- [ ] 地形圖是否恰好三塊,且未解釋為什麼三塊?
- [ ] 6-3 是否為「手足、同輩」而非「你的下一代」?
- [ ] 三組補償論點是否都落地(關係軸、旬空、宮位遞進軸各至少用一次)?
- [ ] 1-1 第二幕機制條目是否 ≥6 條?
- [ ] 旬空是否寫成「打折」而非「凶」?
- [ ] confidence 低時,八章是否都用保守判定的敘事,處方是否已切 conservative?
- [ ] 「沒有時辰」是否只在命盤頁一行標註與附錄各出現一次,八章內文零提醒?
- [ ] 命盤頁是否**不列**真太陽時校正欄?
- [ ] 附錄解鎖清單的機動條是否優先用「缺中神不成局」?

## Step 4:輸出(雙檔交付)

1. 依 `references/report-layout.md` 的標記語法寫成單一 markdown:`@meta`/`@pillars`/`@chart`/`@interactions`/`@dayun`/`@keyyears` 開頭,接八章,再接 `@appendix`、`@letter`
2. 存為 `{稱呼}_命格書_三柱_{日期}.md`
3. 渲染 PDF:
   ```bash
   python3 {skill}/scripts/build_mingge_book.py --md "報告.md" --out "報告.pdf" --fonts ~/fonts-web
   ```
   首次使用需先依 report-layout.md 備妥思源字型;產出後跑該檔的「交付前版面檢查」
4. 兩個檔案一起交付。報告本體不放免責聲明(維持沉浸感);可在交付訊息中口頭提醒屬娛樂與自我探索性質

## 品質紅線(違反即失敗)

1. **虛構時柱**——文章或 JSON 出現任何時柱干支、時柱十神、子女宮論斷、第四塊地形、「你的時柱應該是」之類推測。三柱版第一死罪
2. **論點密度低於 v6**——三組補償論點沒跑滿、地形圖第二幕機制少於 6 條、力量值沒出場。第二死罪
3. **三層寫法退化成一層**——只有命理術語沒有日常場景,或只有場景沒有數字依據
4. 章節之間命理判定矛盾(最常見:財運篇忘記身弱、大運篇搞錯用神;三柱版新增:關係軸查出合化卻沒回頭校正力量值)
5. 場景還原退化成形容詞(「你很敏感」❌ →「別人一句話你在心裡重播十幾次」✓)
6. 干支、旬空、流年算錯——一律程式驗算;JSON 沒有的年份不要現場心算硬加
7. 力量值跨盤比較(「你的官殺比別人高」)——六字盤點的數值只能盤內比
8. 論文腔入侵(「綜上所述」「首先/其次」)——全書維持台灣口語繁體中文
9. 不確定性寫成免責聲明腔——保守判定要寫成斷語,詳見 writing-rules 第 12 條
10. 旬空寫成災厄、關係軸留在術語層、宮位軸寫成三句並列
11. 版面自由發揮——色票、版式、命名不得逐份重新設計,一律照 report-layout.md
12. 一封信裡出現術語——那一頁是人對人,不是命理師對客戶
13. 對讀者現實生活的重大決策(離職、投資、分手、接班)只給「命理時機」不給「結構化建議」——處方必須是讀者可自主判斷的行動框架,不是替他做決定
