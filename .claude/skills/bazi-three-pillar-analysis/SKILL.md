# 三柱論命(BaZi Three-Pillar Analysis)

把年月日三柱轉譯成「讓人起雞皮疙瘩」的心理側寫式命理報告。與四柱版共用同一條翻譯流水線:**命盤依據 → 心理翻譯 → 生活場景還原 → 行動處方**。

**定位:三柱論命是傳統命理處理「時辰不詳」的正規做法,不是殘缺版。**日主、月令、配偶宮(日支)、大運排列、流年干支全部不受缺時柱影響——四章骨架完整保留,只是部分判定要換一套「承認不確定性」的引擎。

## 與四柱版的一致性契約

三柱版是四柱版的**同級姊妹版**,不是簡化版。以下三個維度必須完全一致:

| 維度 | 一致性要求 |
|---|---|
| **論點密度** | 缺時柱拿掉的論點,由三組三柱專屬論點補回(關係軸、旬空、宮位遞進軸),總量與四柱版相當——見 stage1-engine.md「論點總量守恆」 |
| **版面** | 兩版共用 `references/report-layout.md` 與 `scripts/build_report_pdf.py`,同一組色票、同一套版式;差異僅限封面命柱卡數量 |
| **風格** | 兩版共用同一套寫作鐵律;三柱版僅多第 11 條(不確定性的寫法),不改動前 10 條 |

## 時柱缺位的三類影響(全文設計基準)

| 類別 | 內容 | 處理方式 |
|---|---|---|
| 直接消失 | 時柱十神、時支藏干、時柱神煞、子女宮/晚年宮 | 相關主題整篇不寫,**嚴禁虛構或硬掰** |
| 精度下降 | 身強弱(證據從八字變六字)、五行分布、用忌神 | Stage 1 跑「翻盤測試」定 confidence,保守判定 |
| 完全不影響 | 日主定性、月令、配偶宮(日支)、三柱關係軸、旬空、大運排列、流年干支 | 照四柱版原樣處理,力度不打折 |

## 執行流程總覽

```
[收集輸入] → [Stage 1:三柱排盤引擎,十四步推導鏈 → 命盤技術檔案 JSON(含 confidence)]
           → [Stage 2:依 JSON 逐章寫作(性格→財運→感情→大運)]
           → [自檢清單] → [輸出 .md 報告 + 依版面規範產出 PDF]
```

**鐵則:Stage 1 的 JSON 是唯一事實來源。四章所有論述必須可回溯到 JSON 的具體欄位,絕不在寫作中途改變身強弱判定、用忌神、流年機制。JSON 裡沒有的時柱資訊,文章裡一個字都不能出現。**

## Step 0:收集輸入

必要:三柱(年柱/月柱/日柱干支),或出生年月日(國曆/農曆擇一,標明清楚)。

**兩個必問(三柱版專屬):**
1. 「出生時間真的查不到嗎?」——提示可查出生證明、戶政資料、醫院記錄、問長輩。查得到就升級改用 bazi-deep-analysis 跑完整四柱,品質更高。查不到再繼續。
2. 「家人有沒有印象是白天還是深夜出生?」——若可能在晚上 11 點(23:00)之後出生,日柱有換日爭議,**日柱本身存疑**。此時在報告開頭標註「若確認為深夜出生,建議以隔日日柱重排核對」,不可裝作沒這回事。

建議追問(缺了也能跑,但品質下降):
- 稱呼、性別(影響財官星的感情解讀方向、大運排列方向)
- 出生年份(用於計算流年對應歲數)
- **大運排列與起運歲數**(若未提供,依月柱+年干陰陽+性別推排並標註為推算值;不知時辰時起運歲數必然是推算值,一律給 ±1 歲彈性,並建議用排盤軟體核對)
- **user_context**(職業、興趣、現況)——這是個人化注入的殺手級素材,場景還原時錨定到使用者真實生活,命中率大幅提升

若使用者給出生年月日而非干支:年月日三柱換算不涉及時辰與真太陽時,風險比四柱低,但月柱仍有節氣交界日問題——生日落在節氣交替前後兩天內時,先驗算節氣再定月柱,並標註「建議用排盤軟體核對」。**干支、旬空、流年一律程式驗算,不心算**。

## Step 1:三柱排盤引擎(Stage 1)

讀取 `references/stage1-engine.md`,依其十四步推導鏈產出命盤技術檔案 JSON。

要點:
- 推導必須依序執行,不可跳步(日主→身強弱+翻盤測試→五行→**三柱關係軸**→十神→矛盾對→神煞→**旬空**→用忌神→**宮位遞進軸**→大運→關鍵流年→配偶宮→時辰解鎖)
- **身強弱判定是全文總開關**,三柱版多一道「翻盤測試」:假設缺失的時柱是最幫身/最剋洩的極端情況,判定會不會翻?不會翻=confidence 高,照寫;會翻=採保守的中和偏向判定,處方降風險
- **三組補償論點務必跑滿**(關係軸、旬空、宮位遞進軸)——這是三柱版維持論點密度的關鍵,少跑一組報告就會比四柱版薄
- 十神只論年月日三柱;宮位意涵:年柱=長輩/家世/早年,月柱=事業宮/社會我,日支=配偶宮/私我。**時柱的子女/晚年/私領域主題整份報告不碰**
- 矛盾對(2~3 組)決定性格篇的章節骨架;某十神整組缺席時,「缺席」本身就是論點
- 關鍵流年只挑與年月日三支及天干有明確互動機制的年份;連續構成三合/三會者併入 key_windows

先把完整 JSON 呈現給使用者(或寫入工作檔),確認無誤再進 Stage 2。若使用者對判定有異議(如身強弱),在 Stage 1 修正後才續寫,不可在章節裡「將錯就錯」。

## Step 2:章節文案引擎(Stage 2)

1. 先讀 `references/writing-rules.md`——十一條寫作鐵律 + 風格範例(第 11 條是三柱版專屬:不確定性的寫法;另附三柱新素材的寫法)
2. 再讀 `references/chapter-templates.md`——四章各自的節次結構與任務、新素材配置表、三柱版收尾附註
3. 依序寫四章:性格篇 → 財運篇 → 感情篇 → 大運篇(順序有商業邏輯:被看穿→有盼頭→有事做→有時間表,不可亂排)

每章寫完立即對照該章模板的節次要求檢查,缺節即補。**節次骨架與四柱版完全相同(4章×4節),新素材餵進既有節次,不另開新節。**

## Step 3:自檢清單(交付前必跑)

四柱版共通:
- [ ] 每個論點是否走完四步公式(依據→翻譯→場景→處方)?
- [ ] 性格描述是否用矛盾結構(A 但 B)而非形容詞堆砌?
- [ ] 全文是否有 2~3 處內心 OS 直寫(不多不少)?
- [ ] 所有年份預測是否附命理機制(沖/合/透)?
- [ ] 所有負面判斷是否附條件式出口(「只要你……」)?
- [ ] 建議是否具體到「明天就能做」?(顏色到色系、年份到干支、動作到句式)
- [ ] 四章的身強弱、用忌神、大運定調是否與 Stage 1 JSON 完全一致?
- [ ] 有 user_context 時,是否至少在財運篇與感情篇各做一次個人化錨定?
- [ ] 感情篇親密段落是否維持「氛圍與情緒共鳴」層次、點到為止?

三柱版專屬:
- [ ] 全文是否零時柱內容?(未出現任何時柱干支、未寫子女宮/晚年宮論斷)
- [ ] 三組補償論點是否都落地到章節?(關係軸、旬空、宮位遞進軸各至少用一次)
- [ ] 旬空是否寫成「打折」而非「凶」?
- [ ] 身強弱若 confidence 為低,四章是否都用了保守判定的敘事方向,且處方避開高風險絕對斷語?
- [ ] 「沒有時辰」是否只在開頭標註與結尾附註各出現一次,中間章節零提醒(不打斷沉浸感)?
- [ ] 報告結尾是否附「時辰解鎖清單」,且機動一條優先用「缺中神不成局」?

## Step 4:輸出(雙檔交付)

1. 合併四章為單一 markdown 報告,開頭附:稱呼、三柱(年柱/月柱/日柱)、「時辰未知,以三柱論命」一行標註、產出日期;結尾附「時辰解鎖清單」
2. 存為 `{稱呼}_三柱論命解析_{日期}.md`
3. 依 `references/report-layout.md` 產出排版完成的 PDF:
   ```bash
   python3 {skill}/scripts/build_report_pdf.py --md "報告.md" --out "報告.pdf" --fonts ~/fonts-web
   ```
   首次使用需先依 report-layout.md 備妥思源字型;產出後跑該檔的「交付前版面檢查」
4. 兩個檔案一起交付。報告本體不放免責聲明(維持沉浸感);可在交付訊息中口頭提醒屬娛樂與自我探索性質

## 品質紅線(違反即失敗)

1. **虛構時柱**——文章或 JSON 出現任何時柱干支、時柱十神、子女宮論斷、「你的時柱應該是」之類推測。這是三柱版的第一死罪
2. **論點密度低於四柱版**——三組補償論點沒跑滿就交件,報告會明顯比四柱版薄,這是三柱版的第二死罪
3. 章節之間命理判定矛盾(最常見:財運篇忘記身弱、大運篇搞錯用神;三柱版新增:關係軸查出合化卻沒回頭校正強弱)
4. 場景還原退化成形容詞(「你很敏感」❌ →「別人一句話你在心裡重播十幾次」✓)
5. 流年干支或旬空算錯——一律程式驗算,不確定就以 Stage 1 JSON 為準,JSON 沒有的年份不要現場心算硬加
6. 論文腔入侵(「綜上所述」「首先/其次」)——全文維持台灣口語繁體中文
7. 不確定性寫成免責聲明腔——「因為沒有時辰所以僅供參考」這類句子出現在章節內文=失敗;保守判定要寫成斷語(「你走的是中和偏弱的路線」),詳見 writing-rules 第 11 條
8. 旬空寫成災厄、關係軸留在術語層、宮位軸寫成三句並列——見 writing-rules「三柱新素材的寫法」
9. 版面自由發揮——色票、版式、命名不得逐份重新設計,一律照 report-layout.md
10. 對讀者現實生活的重大決策(離職、投資、分手)只給「命理時機」不給「結構化建議」——處方必須是讀者可自主判斷的行動框架,不是替他做決定
